# 知课教务 · 教务管理系统交互演示

一个纯静态、无后端的教务管理系统演示，供课程作业展示与方案对齐使用。四类角色从同一入口进入，覆盖开课申请、教务审核、选课候补、课表、成绩、评教与菜单权限联动。

> 演示数据只保存在浏览器 `localStorage`，不连接任何真实教务库。

## 在线访问

**已部署：** <https://Sueporee.github.io/jwc-demo/>

本仓库根目录就是站点根目录，无需构建。

## 可以重点看的交互

1. **选课幂等与容量**：已选课程退课会释放名额，并按 FIFO 队列递补 1 人；`CS201` 的候选队列里有一名时间冲突学生，会被标记过期并跳过。
2. **满员候补**：`计算机网络` 满员，学生加入候补后显示排队位次；教务把容量 +5 后，学生自动递补并收到通知。
3. **开课审核闭环**：教师提交申请 → 教务通过并发布教学班 → 学生选课中心出现新课程；退回时必须填写原因。
4. **成绩两段式**：教师提交后锁定 → 教务审核 → 发布后学生可见；未发布时学生端只显示“待发布”。
5. **菜单权限联动**：管理员在“菜单管理”取消学生的某个菜单，保存后学生侧栏隐藏；直接访问对应 hash 路由会进入 403。
6. **并发演示**：选课中心右上角“并发抢课演示”，模拟 30 个请求抢 1 个名额，展示 1 成功、29 已满。
7. **移动端**：窄屏下侧栏收起，课表切换为按天列表，表格可横向滚动。

## 本地运行

任选一种静态服务器：

```bash
# Python
python -m http.server 8765

# Node
npx serve .
```

然后访问 `http://127.0.0.1:8765/`。

直接双击 `index.html` 也能打开，但建议用本地服务器，避免个别浏览器对 `file://` 的限制。

## 发布到 GitHub Pages

### 最快：浏览器上传，无需安装 Git

1. 登录 GitHub，新建一个 **Public** 仓库，名字填 `jwc-demo`，不要勾选初始化 README。
2. 进入空仓库，点 **Add file → Upload files**。
3. 把本目录里的 `index.html`、`styles.css`、`app.js`、`favicon.svg`、`og-cover.png`、`404.html`、`README.md`、`.nojekyll` 一起拖进去（不要拖外层 `jwc-demo` 文件夹），提交。
4. 打开 **Settings → Pages**：Source 选 **Deploy from a branch**，Branch 选 **main**，目录选 **/ (root)**，保存。
5. 等 1–2 分钟，访问 `https://<你的用户名>.github.io/jwc-demo/`。

### 命令行方式

前置条件：本机有 Git，并已登录 GitHub（`gh auth login` 或配置 SSH / PAT）。

```bash
cd jwc-demo
git init
git add .
git commit -m "feat: add 知课教务 interactive demo"

# 在 GitHub 新建空仓库 jwc-demo，然后：
git remote add origin https://github.com/<你的用户名>/jwc-demo.git
git branch -M main
git push -u origin main
```

推送后按上面的 **Settings → Pages** 设置即可。

## 设计说明

- 字体：Manrope + Noto Sans SC；中文回退微软雅黑。
- 主色 `#2f6bff`，深色侧栏 `#15171c`，浅灰背景 `#f5f6f8`。
- 卡片全边框、8px 间距体系、无渐变背景；仅 Hero 标题使用文本渐变。
- 支持键盘焦点、`prefers-reduced-motion`、移动端断点 980px / 700px。
- 数据与文案为虚构演示，不对应任何真实学校、教师或学生。

## 与需求文档的对应

本演示对应当前课程项目的七项需求描述：

- 开发目标：登录入口、四类角色工作台、选课/成绩/评教闭环。
- 角色设置：学生、教师、教务人员、系统管理员。
- 权限点位：登录层、菜单/页面层、按钮/接口层、数据层。
- 功能需求：开课、审核、教学班、内容版本、选课、候补、课表、成绩、评教、通知、系统管理。
- 核心流程：开课审核、选课候补、成绩发布、评教。
- 预计风险：并发超卖、递补资格、计数漂移、权限绕过、采用率、范围蔓延、通知失败、旧数据质量。
- 验收标准：功能、权限、并发/幂等、候补、成绩、数据、体验、审计。
